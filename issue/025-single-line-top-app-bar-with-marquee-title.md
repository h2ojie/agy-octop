# Issue 025: 顶栏管家名与会话标题单行化、跑马灯滚动与移除抽屉汉堡按钮 (v1.0.26)

## 1. 背景与用户需求
用户反馈：
> “把标题跟管家名字放到同一行。
> 例如图片里面，育儿管家放在左边，然后显示10月16日标题，如果标题很长的话，就做一个滚动效果。最左边的那个按钮先去掉，因为我们全屏右滑的话就能唤出这个抽屉了，这样的话我们就省了一行的空间可以来显示消息，你试一下，看看效果。”

附带当前手机截图：
- 原先顶部 `TopAppBar` 纵向分为两行（主标题“育儿管家” + 副标题“10月16日”），占用了两行纵向空间。
- 左上角常驻汉堡菜单按钮 `[☰]`，而用户通过手势从屏幕左侧向右滑已可直接唤出侧边栏抽屉，汉堡按钮挤占了宝贵的水平横向宽度。

---

## 2. 方案设计与交互重构

### 2.1 移除冗余的左侧汉堡按钮 (`navigationIcon`)
- 废弃 `TopAppBar` 的 `navigationIcon` 汉堡按钮，释放左侧横向宽度。
- 手机端用户在全屏任意时刻从左侧边缘向右滑均可直接滑出专家会话抽屉（`ModalNavigationDrawer` 原生手势）。
- 同时在标题整行挂载静默点击监听，点击顶栏文字同样可顺畅唤出抽屉，提供双重便捷唤起途径。

### 2.2 专家名称与会话标题同排对齐
在 `TopAppBar` 的 `title` 槽位中采用横向居中对齐的单行 `Row`：
- **左侧**：突出显示当前智能体名称（如“育儿管家”），字号 `16.5.sp`，加粗显示，最大行数限制为 1。
- **中间**：微型分隔符 `·`（半透明浅灰）。
- **右侧**：当前会话标题（如“10月16日”），字号 `13.5.sp`，占据剩余横向空间（`Modifier.weight(1f)`）。

### 2.3 超长标题自适应跑马灯滚动 (`basicMarquee`)
为会话标题配置 Compose 原生 Foundation 的 `basicMarquee` 动画：
```kotlin
Text(
    text = displayTitle,
    fontSize = 13.5.sp,
    color = MaterialTheme.colorScheme.onSurfaceVariant,
    maxLines = 1,
    modifier = Modifier
        .weight(1f)
        .basicMarquee(
            iterations = Int.MAX_VALUE,
            velocity = 30.dp
        )
)
```
- **短标题**（如“10月16日”或“新对话”）：在剩余空间内完整静态呈现，端庄大方。
- **超长标题**（如多段文字或长病历分析主题）：在停顿 1.2 秒后以 30dp/s 的柔和速度横向循环滚动播放，既不截断关键信息（不出现生硬省略号），又不换行占位。

### 2.4 垂直屏效最大化
通过将原先双行文字收缩并入单行，节省了整整一行的垂直高程，为下方的聊天流与提问卡片留出了更多视野空间。

---

## 3. 验证要点
1. **单行布局**：“育儿管家 · 10月16日”整齐排在单行内，左侧干净通透无汉堡菜单图标。
2. **长标题跑马灯**：切换或新建长名称会话时，标题文本自动横向柔顺滚动，不挤压管家名称。
3. **抽屉呼出体验**：屏幕右滑或直接轻触顶栏文字，侧边抽屉秒级划出。
4. **右侧操作菜单**：右侧 `[⋮]` 按钮不受任何影响，新建会话与设置菜单正常弹出。
