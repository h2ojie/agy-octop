# Issue 012: Markdown 表格多列不对齐、单元格独立宽度导致垂直网格线错位优化

- **问题编号**：ISSUE-012
- **发现时间**：2026-10-15
- **修复时间**：2026-10-15
- **涉及模块**：
  - `app/build.gradle.kts`: 版本递增至 `v1.0.13` (versionCode = 14)；
  - `MarkdownRenderer.kt`:
    - 重构 `TableBlock` 渲染管线；
    - 废除原先每一行独立定义 `Row` + 独立 `widthIn(min, max)` 的做法（此前导致每行同列单元格宽度各不相同、垂直分割线犬牙交错）；
    - 实现统一列宽计算引擎 `columnWidths`：全量扫描整张表所有行（表头与数据行），根据最长单行文字字符权值（全角/中文 14dp，半角/英文 7.5dp）动态测算每一列最佳宽度并限制在 `[88.dp, 240.dp]` 区间；
    - 所有行的第 $j$ 列单元格严格应用相同的 `columnWidths[j]`，彻底拉直所有垂直网格线；
    - 每行使用 `Modifier.height(IntrinsicSize.Min)`，单元格与垂直分割线 `Modifier.fillMaxHeight()` 贯通整行高度，自动适应单元格文字折行；
    - 表格支持圆角边框、表头加深背景、斑马纹奇偶行交替高亮及平滑水平滚动。
- **状态**：已解决 (Resolved)

---

### 一、 问题背景与用户痛点

用户在查看“我的持仓专家”发出的《右侧重仓狙击雷达》看板表格时，反馈“表格每一列都对不齐”。

**根因分析**：
原实现中，每个 `TableRow` 只是简单的 Compose `Row`，内部各个 `TableCell` 直接应用了 `widthIn(min = 80.dp, max = 220.dp)`。
- 表头的第 0 列为“标的”（2 个字），宽度被压缩在 80dp 左右；
- 第 1 行的第 0 列为“阿里巴巴 (09988)”（12 个字符），宽度自动被内容撑大至约 130dp；
- 第 2 行的第 0 列为“美团 (03690)”，宽度约为 105dp；
- 第 3 行的第 0 列为“小米集团 (01810)”，宽度约为 120dp。

由于第 0 列各行宽度完全不一致，导致第 1 列的起始 X 坐标在每行各不相同，整张表格的所有垂直分割线全部错位错开，严重破坏了表格的可读性与专业质感。

---

### 二、 修复方案

1. **预解析全表结构**：在组合阶段将 `TableBlock` 扁平解析为统一的 `List<Pair<Boolean, List<AnnotatedString>>>`。
2. **全局统一测算每列宽度**：
   - 提取最大列数 `numCols`；
   - 遍历各行各列，按中英文字符权重与换行折行测算各列所需最大内容宽度；
   - 映射为统一列宽列表 `columnWidths: List<Dp>`。
3. **等宽对齐与贯通分割线**：
   - 每一行的第 $j$ 列固定为 `Modifier.width(columnWidths[j])`；
   - 行应用 `Modifier.height(IntrinsicSize.Min)`；
   - 列间插入 `fillMaxHeight().width(0.75.dp)` 细线，实现顶天立地的标准表格网格；
   - 行间插入统一粗细的水平分割线，整体外加圆角边框与斑马纹。

---

### 三、 验证结果

- `./gradlew assembleDebug` 编译通过。
- 表格每一列垂直网格线 100% 对齐，各列内容按最大宽度整齐排列并支持水平平滑滑动。
